# Harmony Decor — دليل تشغيل الموقع بالعربية

هذا مشروع موقع Harmony Decor الاحترافي ثنائي اللغة (عربي/إنجليزي)، بهوية بيج وبني وقهوة، ولوحة إدارة خاصة، وقاعدة بيانات Supabase، وتجهيز نشر على Cloudflare Workers عبر OpenNext.


## لوحة الألوان المعتمدة

تم اعتماد هوية **Warm Architectural Luxury** بدرجات هادئة وغير صفراء:
- الخلفية العاجية الدافئة: `#F3F0E9`
- البطاقات الفاتحة: `#FAF8F3`
- الرملي الناعم: `#DDD3C5`
- Greige للتفاصيل: `#B8AA99`
- Mocha للأزرار والإبرازات: `#806653`
- Espresso للنصوص والأقسام الداكنة: `#382C25`

## 1) المتطلبات
- Node.js 20.18 أو أحدث (يفضل LTS).
- حساب Supabase.
- حساب Cloudflare.
- Git اختياري لإدارة الإصدارات.

## 2) تشغيل المشروع محلياً
1. فك ضغط الملف.
2. افتح مجلد المشروع في VS Code.
3. افتح Terminal داخل المجلد.
4. نفّذ:
   ```bash
   npm install
   ```
5. انسخ `.env.example` إلى ملف باسم `.env.local`.
6. ضع رابط مشروع Supabase ومفتاح `anon/public` في `.env.local`.
7. شغّل:
   ```bash
   npm run dev
   ```
8. افتح `http://localhost:3000`.

## 3) إعداد قاعدة البيانات
1. أنشئ مشروعاً جديداً في Supabase.
2. افتح SQL Editor.
3. افتح الملف `supabase/schema.sql` وانسخ محتواه كاملاً إلى SQL Editor ثم Run.
4. من Authentication > Users أنشئ حساب المسؤول (البريد وكلمة المرور).
5. انسخ UUID الخاص بالمستخدم.
6. نفّذ في SQL Editor:
   ```sql
   insert into public.admin_users(user_id, role)
   values ('ضع-UUID-المستخدم-هنا', 'admin');
   ```
7. أضف رابط Supabase ومفتاح anon إلى `.env.local`.
8. لا تضع `service_role` في الواجهة أو في متغير يبدأ بـ `NEXT_PUBLIC_`.

## 4) فتح لوحة الإدارة
- الرابط: `http://localhost:3000/admin/login`
- سجّل الدخول بالبريد وكلمة المرور اللذين أنشأتهما في Supabase.
- بعد نجاح الدخول ستصل إلى `/admin`.
- من Projects يمكنك إضافة مشروع وتعديله ونشره أو إبقاؤه مسودة.
- من Messages تستطيع قراءة الرسائل الواردة.
- صلاحيات الإدارة تعتمد على جدول `admin_users` وسياسات RLS، وليس على إخفاء الرابط فقط.

## 5) إضافة الصور
النسخة الحالية تقبل رابط صورة مباشر في حقل Cover image URL. الأفضل في مرحلة الإنتاج إنشاء Storage bucket باسم `portfolio` في Supabase، ورفع الصور إليه، ثم حفظ الرابط العام في المشروع.
يمكن إضافة واجهة رفع مباشرة إلى Storage كخطوة تطوير لاحقة. لا ترفع ملفات ضخمة بلا ضغط؛ استخدم WebP/AVIF قدر الإمكان.

## 6) النشر على Cloudflare
المشروع يستخدم OpenNext for Cloudflare لأن Next.js لا يُنشر كملفات Static عادية عند استخدام ميزات الخادم وقاعدة البيانات.

1. ثبّت الحزم:
   ```bash
   npm install
   ```
2. سجّل الدخول إلى Cloudflare:
   ```bash
   npx wrangler login
   ```
3. أنشئ إعدادات الإنتاج/الأسرار في Cloudflare Workers:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   أضفهما كـ Variables/Secrets في إعدادات Worker. لا تضع مفتاح `service_role` في المتصفح.
4. نفّذ:
   ```bash
   npm run deploy
   ```
5. اربط الدومين من لوحة Cloudflare بعد نجاح النشر.

> قد تتغير متطلبات توافق Next.js وOpenNext وWrangler مع الوقت. إذا أظهر البناء خطأ توافق، راجع إصدارات OpenNext الرسمية وحدّث الحزم المتوافقة قبل النشر.

## 7) هيكل المشروع
- `src/app/[locale]`: صفحات الموقع بالعربية والإنجليزية.
- `src/app/admin`: لوحة الإدارة.
- `src/app/api/contact`: استقبال رسائل نموذج التواصل.
- `src/components`: مكونات الواجهة والنماذج.
- `src/lib`: الترجمة واتصال Supabase والأنواع.
- `supabase/schema.sql`: الجداول والفهارس وسياسات RLS.
- `wrangler.jsonc` و`open-next.config.ts`: إعداد Cloudflare.

## 8) ما الذي تتضمنه النسخة الحالية؟
- واجهة رئيسية بتصميم بيج/بني.
- تحويل بين العربية والإنجليزية مع RTL للعربية.
- أقسام التعريف والخدمات والمشاريع والتواصل.
- صفحة قائمة المشاريع وصفحة تفاصيل لكل مشروع.
- تسجيل دخول إداري باستخدام Supabase Auth.
- لوحة إحصائيات أولية.
- إضافة وتعديل وحذف ونشر المشاريع.
- عرض الرسائل الواردة.
- سياسات RLS لحماية عمليات الإدارة.

## 9) ما الذي يحتاج استكمالاً قبل اعتبار الموقع إنتاجياً؟
- محرر بيانات الملف الشخصي من لوحة الإدارة (الجدول جاهز).
- رفع الصور من لوحة الإدارة إلى Supabase Storage بدلاً من لصق الرابط.
- محرر معرض الصور المتعددة وترتيبها.
- إدارة الخدمات والشهادات وآراء العملاء من لوحة الإدارة.
- إعداد SEO لكل مشروع وOpen Graph.
- حماية إضافية من الرسائل المزعجة (CAPTCHA / rate limiting).
- إضافة اختبارات، مراقبة أخطاء، وسياسة نسخ احتياطي.
- مراجعة المحتوى والصور والبيانات الحقيقية قبل النشر.

## 10) ملاحظات أمنية
- لا تستخدم حساباً عاماً مشتركاً للإدارة.
- فعّل MFA لحساب Supabase وCloudflare.
- لا تكشف مفاتيح `service_role`.
- أضف المسؤولين من SQL يدوياً بعد التحقق من UUID.
- لا تعتبر إخفاء رابط `/admin` حماية؛ الحماية الفعلية هي Auth + RLS.


## اسم الموقع وهوية المشروع
- الاسم التجاري الظاهر في الموقع: **Harmony Decor**.
- تم تحديث عنوان الصفحة واسم التطبيق وشعار الترويسة والأيقونة.
- تم الإبقاء على اسم Cloudflare Worker الحالي `eng-ghazwan` داخل `wrangler.jsonc` حتى لا يتغير عنوان النشر الحالي عند إعادة النشر.
- لم يتم تضمين `.env.local` أو أي مفاتيح سرية داخل ملف ZIP. أعد وضع ملف البيئة المحلي لديك بعد فك الضغط، وأضف متغيرات الإنتاج في إعدادات Cloudflare.

## قبل النشر النهائي
هذه نسخة مشروع كاملة من ناحية ملفات التطبيق، لكنها تحتاج بيانات مشروع Supabase الفعلية، وتشغيل SQL الموجود في `supabase/schema.sql` على قاعدة البيانات، وإنشاء حساب المدير، ثم إعداد متغيرات البيئة في Cloudflare. لا يمكن اعتبار الموقع منشوراً أو متصلاً بقاعدة البيانات قبل إكمال هذه الخطوات والتحقق منها.
